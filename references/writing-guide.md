# 公众号写作指南

用于环节 C（写作）的成稿规范。输出到 `15-Published 发布/`。

## 文章结构（正文原稿与写作信息分离）

```
正文原稿 {标题}.md（只含正文，不含任何辅助信息）：
标题（≤30字，有吸引力、不标题党）
作者署名
封面图（占位符）

导语（100-200字）：抛出现象/问题，给读者看下去的理由

## 正文分 2-4 个小节
### 小节标题1：每节聚焦一个分论点
### 小节标题2：
### 小节标题3：

结尾（100-200字）：总结观点，或抛出一个开放性问题引发讨论

写作信息 写作信息-{标题}.md（辅助信息，仅供审阅，不进公众号正文/草稿）：
备选标题：3-5 个，覆盖不同传播方向（事实型/观点型/悬念型）
内容验真：文末"来源说明"——核心事实/数据出自哪篇采集文章
图位清单：共需几张图、每张位置/建议内容/建议比例
摘要：60 字以内，公众号填写用
```

## 写作要求

1. **导语抓人**：第一段就要让读者知道"这篇和我有什么关系"
2. **观点增量**：不是复述采集素材，而是有明确的作者立场/分析/建议
3. **素材引用**：引用具体事实、数据、案例时标注来源（公众号名+标题）
4. **图文搭配**：每 400-600 字配 1 张图，图片说明写清内容
5. **口语化但不失专业**：避免 AI 腔（"总而言之""综上所述""值得注意的是"等套话）
6. **字数**：800-2500 字为宜，视选题而定

## 写作类型（按读者需求判断，先判断再写）

| 读者需求 | 主类型 | 写法重点 |
|---|---|---|
| 想知道发生了什么、为什么重要、后续影响 | 新闻热点类 | 事实链清晰、时间线准确、点出影响与争议；标题靠信息量吸引 |
| 想理解概念、机制、方法、趋势 | 专业解读类 | 概念解释、机制拆解、案例验证；标题靠"我能讲透什么"吸引 |

- 复合型（如热点+解读）确定一条主线，以主类型写法统摄全文，不简单拼接
- 不套用同一模板，每篇根据主类型调整结构重心

## 写作红线（事实与标题）

1. **不编造事实**：不虚构数据、来源、采访、人物经历、现场细节、图片出处
2. **不把推测写成事实**：未经核实的信息用"据公开报道""目前尚未确认""更稳妥的说法是"等边界表达
3. **不标题党**：标题可以有悬念、冲突、情绪，但不能虚假承诺、夸大、恐吓
4. **必须有增量**：每篇至少一种增量——事实/解释/认知/叙事增量，避免复述素材和"正确废话"

## 联网核查检查点

- 引用采集之外的事实（历史背景、行业数据、公司信息、政策）时，先联网核实
- 联网无法核实的，标注边界词，不写死
- 当日采集素材内的信息以原文为准，引用时标注来源（公众号名+标题）

## 内容验真格式（文末"来源说明"）

```markdown
## 来源说明
- 核心事实/数据：出自《采集文章标题》（公众号名 · 日期）
- 外部引用：来源链接或来源说明
- 无法核实项：标注"据公开报道/尚未确认"
```

## 配图处理（占位符模式，写作时不生图）

**核心规则：写作阶段图片一律写占位符 `![图N-建议内容]()`，不生成、不引用真实图片。文章写完后由用户选择配图方式，全部配齐才可发布。**

1. **占位符**：统一格式 `![图N-建议内容]()`，N 为序号。如 `![图1-封面-沙漠星球画面]()`、`![图2-剧本工作台]()`
2. **图位清单**：交付成稿时列出——共需几张、每张位置/建议内容/建议比例（封面 2.35:1，正文 3:2 或 16:9）
3. **配图方式三选一**（用户决定）：
   - 手动配图（推荐）：用户把图片**按占位符名字命名**（如 `图1-封面-沙漠星球画面.jpg`）放入 `images-{英文短名}/`，执行者运行 `resolve_images.py` 自动匹配替换；文件名与占位符一致即可，支持忽略空格差异
   - AI 生图：执行者生成原创图（无水印无文字）并替换占位符
   - 混合：用户放 M 张（按名命名）→ 跑 `resolve_images.py` 匹配 → 剩余未匹配清单由 AI 生成补齐
4. **复用采集图规则**：用户可手动使用 Inbox 原始中无水印/无账号标识的图片；带账号水印（如 APPSO）的图不得用于发布。复用图需在交付时说明来源
5. **内容匹配规则**：手动放图时，图片内容应与占位符建议内容一致（如占位符写"节点网络示意图"，就不要放数据散点图）。执行者发现不一致时，先向用户说明差异并确认，不默认放行；用户明确选择保留后，图注改为匹配实际内容
6. **来源合规规则**：禁止使用第三方网站截图/含明显来源标识的图片（英文标题、网站水印、模型榜单、数据图表）用于发布，除非用户明确确认接受风险。发布前检查图片是否疑似第三方来源
7. **文件名与目录名**：图片目录用**纯英文短名**（如 `images-fermat-proof/`），禁止中文、空格、全角标点（Obsidian 解析此类路径不可靠）。**用户手动放图时按占位符中文名命名即可**（复制占位符文字，无需懂英文），`resolve_images.py` 匹配后自动改名为 `img1.jpg`、`img2.jpg`…；AI 生图时文件名直接给 `imgN.jpg`。AI 图生成时 prompt 注明"无任何文字与水印"
8. **发布前检查**：脚本检测到残留 `]()` 占位符时拒绝推送并列出缺图清单
9. **占位符位置可自由调整**：配图脚本按占位符名字（图N）匹配图片，与位置无关——用户可在 Obsidian 自由剪切/移动占位符，不影响配图与发布。**⚠️ 图1（封面）必须保持在正文首图位置**（发布脚本取第一张图为封面）；移动占位符后同步更新写作信息文件的图位清单"位置"列

## 发布前检查清单

- [ ] 标题 ≤ 30 字，无错别字，非标题党（无虚假承诺/夸大）
- [ ] 已给出备选标题 3-5 个（覆盖不同传播方向）
- [ ] 导语、正文、结尾完整
- [ ] 观点有增量，非素材复述
- [ ] 事实/数据有来源标注，无编造事实，推测已用边界词
- [ ] 采集之外的事实已联网核实或标注边界
- [ ] 文末含"来源说明"（内容验真）
- [ ] 无残留占位符 `![...]()`，所有图片已配齐
- [ ] 图片内容与占位符建议内容一致（不一致已向用户确认并更新图注）
- [ ] 图片非第三方网站截图/无来源标识（英文标题、网站水印、模型榜单），或用户已明确确认接受风险
- [ ] 图片为 AI 原创/用户提供/无账号水印图（无水印、无原账号标识）
- [ ] 图片已本地化到 `15-Published 发布/{日期}/images-{英文短名}/`、md 引用路径正确
- [ ] 摘要（公众号填写的摘要）已写好，60 字以内
